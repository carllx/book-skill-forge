# 对抗法则与法官判定指南 (The Crucible Protocol)

本指南专门为“主控 Agent（法官角色）”提供裁决标准，确保 `multi-agent-debate-panel` 的对抗性达到最高烈度。

## 1. “无效妥协”的判定黑名单

当检查子代理的交叉火力报告时，如果发现以下任何一种话术或行为，必须立即将其**驳回重做（Reject & Retry）**：

- **假意融合**：“虽然我们在XX上存在分歧，但我们可以结合一下，在上层用A，底层用B。”（如果这种结合没有严密的逻辑支撑，纯属为了妥协而妥协，直接驳回）。
- **学术媚俗**：“为了照顾读者的耐心/为了易于实现，我同意放宽对有效性的要求。”（专家绝对不能主动放宽自己框架的底线）。
- **无伤大雅的附和**：“我认为这位专家的观点非常有启发性，完全赞同。”（交叉诘问阶段不允许赞同，必须寻找漏洞）。

## 2. 什么是“致命攻击点”？

子代理必须提交至少 2 个致命攻击点才能通过你的 QA 门槛。一个合格的“致命攻击点”必须包含：

1. **原论点引用**：准确指出对手方案中的某个微观设计（例如：在此处使用发光的 3D 柱状图）。
2. **本门理论引证**：必须引用该专家自己所代表的经典文献或框架定理（例如：“根据 Tamara Munzner 的 Expressiveness Principle，3D 柱状图在 2D 平面上会产生遮挡和透视畸变，导致数据表达不忠实”）。
3. **不可逆的破坏性**：证明如果按对手的方案执行，将会导致该领域核心指标的彻底崩溃（如：认知负荷超载、核心数据被掩盖）。

## 3. 法官（主控 Agent）驳回话术示例

当需要打回重做时，你可以使用以下强硬的 `send_message` 模板：

**学术妥协驳回模板：**
> "你的回应质量不可接受。你过多地展示了向 [专家B] 妥协的倾向。作为 [专家A理论] 的捍卫者，你没有尽到你的责任。
> 请重新检视对方关于 [某设计点] 的提议。根据你自己的 [具体定律]，这种设计会带来什么灾难性后果？
> 撤回你的妥协，重新提交一份包含至少 2 处致命反驳的报告，不准使用任何退让性措辞。"

**工程违规驳回模板（OOM 防线）：**
> "你的回应违反了系统工程规范。你的消息长度超过了 50 行，这会导致上下文爆炸风险。
> 严禁直接在消息中返回大段文本。请立即将你的长篇分析写入工作区的临时文件（例如 `scratch/[你的名字]_report.md`），然后在消息中仅向我提供该文件的绝对路径和一段不超过 50 字的摘要结论。重新执行！"

## 4. 终局收敛：什么时候允许结束循环？

由于循环最大迭代次数（TTL）为 5，通常在以下情况你可以宣布终局并撰写最终报告：

1. **理论死锁的机器判定 (Deadlock Heuristics)**：若子代理连续 2 轮针对同一核心设计元素抛出“致命攻击”，且双方都拒绝让步或无法切换策略（即：证明在单一媒介下不可能同时满足两者的要求）。这正是我们想要的“终极真相”。此时不应等待 TTL 耗尽，立即中断循环。
2. **强制提出创新的降维架构**：在触发死锁后，法官代理必须立刻命令处于死锁的专家们：*“现在，我赋予你们一个额外的维度（例如时间轴、交互事件、Z轴深度）。在这个新维度下，你们如何规避冲突？”* 如果他们在新维度下达成一致，即形成“降维解法”。
3. **TTL耗尽**：循环到达 5 次，直接截断，将当前最激烈的交锋点、理论死锁和法官生成的降维解法写入报告。
