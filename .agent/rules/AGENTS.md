# BSF 测试台全局项目规则

## 0. 最高优先级：多维测试目标 (Global Context)
每次处理 BSF 任务时，必须优先理解 [全局愿景与项目宪章](../../docs/PROJECT_CONTEXT.md)。
**核心约束**：BSF 是一个多维度复合测试台。必须主动支持单维度与多维度复合（如 Graphify + Cangjie）的管线搭配。

## 1. 架构与领域 SSOT 约束
必须严格遵守“单一事实来源 (SSOT)”原则，操作前强制阅读对应领域的唯一权威规范：
- [V6 核心目录与沙盒引擎规范](../../docs/ARCHITECTURE.md)
- [评测流程、脱水计分与语义容错规范](../../docs/EVALUATION_GUIDELINE.md)
- [反作弊与客观计分红线](rule_anti_cheating.md) (含沙盒纪律要求)

## 2. 交互准则与双轨制汇报 (Dual-Track Persona)
所有讨论、生成的文档均须使用**中文**。
主控人类是一位**媒体艺术老师**。
内部评测记录使用“脱水数据结构”；向用户汇报时，主控 Agent **必须**使用绝妙的艺术隐喻（如“榨汁机”、“无缝感应的数字艺术工坊”、“无导演剧团”）。

## 3. 双轨制文档自动更新机制 (Dual-Track Documentation Update)
在**存在代码修改或架构变更的写操作任务后**（只读任务除外），主控 Agent **必须强制召唤 Subagent** 自动执行两级文档的同步更新：
1. **专业级**：`docs/` 目录下的技术细节。
2. **小白级**：项目根目录 `README.md` 的隐喻展厅设计。

## 4. 人机交互边界红线 (HCI Guardrails)
在以下场景，禁止 Agent 自主往下执行，必须弹出提示等待人类点击 **Proceed** 或给与指令：
- **管线启动**：无明确参数时，必须提供推荐选项并等待人类选择。
- **环境副作用**：执行 `sync_vendors.py` 或修改底层依赖前，必须获得人类授权。
- **自动重试门禁**：当提取得分不达标触发自动重试时，一旦触碰规定的重试上限，必须上报人工干预。
- **战报终审**：生成评测报告后，管线必须挂起等待人类艺术总监的最终裁定意见。
